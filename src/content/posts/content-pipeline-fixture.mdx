# MDX 语法指南

MDX 让你在编写熟悉的 Markdown 的同时，可以在普通 Markdown 不够用的地方加入组件和 JavaScript 表达式。本指南介绍在以内容驱动的 Astro 站点撰写文章时最常用的语法。

:::note[什么是 MDX？]
`.mdx` 文件本质上仍是 Markdown 文档。标题、列表、链接、图片、代码块等 Markdown 语法依然有效，同时导入、组件、JSX 和表达式作为可选扩展可供使用。
:::

## Frontmatter

每篇文章都以 YAML frontmatter 开头，它定义了文章页面、列表、搜索结果和订阅源使用的元数据：

```yaml
---
title: My MDX Article
published: 2026-08-08
description: A short introduction shown in article previews.
tags: [Markdown, MDX]
category: Guides
draft: false
---
```

让 frontmatter 专注于元数据。导入和 JavaScript 声明应放在闭合的 `---` 分隔符之后。

## 标准 Markdown

MDX 文章的大部分内容应保持为普通 Markdown。这样既保持了源码的可读性，也为 RSS 和 Atom 阅读器提供了有用的静态版本。

```markdown
## A section heading

- A list item
- **Bold text** and *emphasis*
- [A normal link](https://example.com/)

> A blockquote remains a blockquote.
```

## 导入并使用组件

MDX 可以在顶层导入 Astro 组件，并在文档中直接使用。组件名称必须以大写字母开头。

```mdx
import Notice from "../../components/Notice.astro";

export const message = "Props can come from an MDX expression.";

<Notice label={message} />
```

下面的面板就是由本文渲染的一个实际组件：

<ContentPipelineFixture label={componentMessage} />

将组件用于可复用的界面元素或结构化内容。常规叙述请优先使用 Markdown，这样文章能保持可移植性和可读性。

## JavaScript 表达式

顶层的 `export const` 声明可以为文档准备值。使用大括号插入 JavaScript 表达式：

```mdx
export const topics = ["components", "expressions", "extended Markdown"];

This guide covers {topics.length} topics: {topics.join(", ")}.
```

这个实时表达式统计的主题数量为 {topics.length} 个：{topics.join(", ")}。

表达式在构建期间应当是确定性的。诸如 `window` 和 `document` 等仅浏览器可用的 API 应放在组件脚本中，而不是 MDX 模块主体中。

## 提示框

提示框可以突出显示信息，无需自定义组件：

:::tip[使用最简单可行的语法]
叙述文字选择 Markdown，小的动态值使用 MDX 表达式，需要复用标记或行为时使用组件。
:::

````markdown
:::tip[Optional title]
This content is emphasized as a tip.
:::
````

## Wiki 链接

行内 Wiki 链接指向另一篇文章，同时保持句子的可读性。例如，可以继续阅读 [[guide|内容指南]]。

独立的 Wiki 链接会变成一张带可用元数据和封面图的文章卡片：

[[guide]]

```markdown
Read [[guide|the content guide]] for more details.

[[guide]]
```

## 数学与化学

行内数学公式使用单个美元符号，块级公式使用一对。`mhchem` 扩展也可用于化学符号。

爱因斯坦的质能关系式是 $E = mc^2$。

$$
\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}
$$

化学反应式可以写成 $\ce{H2O + CO2 -> H2CO3}$。

```markdown
Inline: $E = mc^2$

Display: $$\int_0^1 x^2\,dx = \frac{1}{3}$$

Chemistry: $\ce{H2O + CO2 -> H2CO3}$
```

## 图片与说明文字

图片的 alt 文本向辅助技术描述图片。Markdown 标题会变成可见的说明文字，可选的 `w-N%` 标记用于控制宽度。

![方形演示图片 w-60%](/images/demos/image-grid-demo/square-1.webp "由 Markdown 图片标题生成的说明文字")

```markdown
![Descriptive alt text w-60%](./image.webp "Visible image caption")
```

有效宽度范围为 `w-1%` 到 `w-100%`。当图片应使用常规响应式宽度时，省略该标记即可。

## 内部与外部链接

使用已配置站点源地址的相对链接和绝对 URL 会被归类为内部链接。指向其他源地址的链接会带上主题配置的外部链接属性。

- 使用相对站点 URL 访问[关于页面](/about/)。
- 与[外部参考](https://example.com/reference)进行对比。

内部内容使用相对路径。诸如 https://example.com/ 的外部源地址会由主题单独分类。

## 编写可移植的 MDX

文章页面、RSS 和 Atom 共享同一个内容管线。交互脚本会从订阅源中移除，但由组件、提示框、Wiki 链接、数学公式、代码组和图片产生的语义化 HTML 仍然可读。

为确保输出可靠：

1. 主要说明文字使用 Markdown。
2. 为图片提供有意义的 alt 文本，为组件提供语义化 HTML。
3. 避免在顶层表达式中使用浏览器全局变量。
4. 确保有用信息在客户端 JavaScript 运行前即可见。
5. 发布前运行 `pnpm test`、`pnpm check` 和 `pnpm build`。

MDX 最适合作为 Markdown 的扩展，而非替代品。先从纯内容开始，仅在能让文章更清晰或更可复用的地方引入表达式和组件。
